# PRD：CSR 文档题注与交叉引用治理 Agent

## 1. 产品概述

### 1.1 产品名称

CSR 文档题注与交叉引用治理 Agent

### 1.2 产品定位

该 Agent 是 AI 写作平台的下游后处理 Agent，面向医药 CSR 中文报告，负责将 AI 生成的非结构化文档初稿治理为具备标准题注、真实交叉引用、编号一致性、可审计记录的交付级文档。

它不负责生成医学内容，而负责解决 AI 写作后的“文档工程合规”问题。

### 1.3 一句话定义

面向医药 CSR 中文报告，自动识别表格、图片、题注和正文引用，完成题注标准化、旧编号到新编号映射、正文引用改写、真实交叉引用创建，并输出可审计的处理报告。

## 2. 背景与问题

### 2.1 AI 写作的“最后一公里”断层

AI 写作平台可以生成 CSR 报告正文，但生成结果通常只是普通文本和普通表格，不具备 Word/WPS 文档中的结构化对象能力。

典型问题包括：

1. 正文中写了“见表 1”或“见表格 14.1.1.2”，但只是普通文本，不能点击跳转。
2. 表格标题是普通段落或表格内文本，不是标准题注对象。
3. AI 生成的编号可能与最终文档编号不一致。
4. 表格重排后，正文引用无法自动更新。
5. 审阅人员需要手动检查题注、编号、引用关系，工作量大且容易出错。

### 2.2 企业级合规要求

在医药 CSR 报告中，“合规”不仅指内容正确，也包括文档结构自洽：

- 编号连续、无重复、无跳号。
- 正文引用与表/图题注一致。
- 交叉引用可点击跳转。
- 字段刷新后编号能自动同步。
- 修改过程可解释、可审计、可追溯。

### 2.3 典型案例

原正文：

```text
基于所有入组人群总结的患者分布见表格14.1.1.2。
```

原表题：

```text
表 14.1.1.2 试验完成情况总结 意向治疗分析集(ITT)
```

Agent 处理后，先将表题转换为标准题注：

```text
表 3 试验完成情况总结 意向治疗分析集(ITT)
```

然后正文同步改写为：

```text
基于所有入组人群总结的患者分布见表格3。
```

其中“表格3”需要是真实交叉引用字段，可点击跳转，并可随题注编号刷新。

## 3. 产品目标

### 3.1 业务目标

1. 降低 CSR 报告后处理成本。
2. 减少人工检查题注和引用的时间。
3. 消除引用断链、错链、编号不一致等低级错误。
4. 提升 AI 生成文档的可交付性。
5. 让处理过程可解释、可追溯、可审计。

### 3.2 用户目标

用户希望通过一句自然语言指令完成文档治理，例如：

```text
请按中文 CSR 报告标准处理全文表格和图片题注，并建立正文交叉引用。
```

系统应自动完成扫描、计划生成、用户确认、执行、审计报告输出。

### 3.3 产品成功标准

1. 能识别 CSR 中文报告中的表格、图片和疑似题注。
2. 能将静态题注转换为标准 WPS/Office 题注。
3. 能建立旧编号到新编号的映射。
4. 能识别正文引用并同步改写。
5. 能创建真实交叉引用。
6. 能区分高、中、低置信度处理项。
7. 能输出可审计的处理报告。
8. 用户能看到每个关键处理环节，不是黑盒执行。

## 4. 目标用户

### 4.1 主要用户

- 医学写作人员
- 临床报告撰写人员
- CSR 文档编辑人员
- 医药企业文档合规审阅人员
- AI 写作平台中的业务用户

### 4.2 用户特点

- 熟悉 CSR 报告结构。
- 不一定熟悉 WPS/Word 高级功能。
- 希望减少手动排版和引用维护。
- 对文档准确性、可追溯性要求高。
- 对黑盒自动修改敏感，需要可查看、可确认、可回溯。

## 5. MVP 范围

### 5.1 聚焦范围

第一版只做中文医药 CSR 报告中的表格/图片题注治理与正文交叉引用治理。

### 5.2 支持对象

| 对象 | MVP 是否支持 | 说明 |
| --- | --- | --- |
| 表格 | 支持 | 识别、题注化、创建引用 |
| 图片 | 支持 | 识别、题注化、创建引用 |
| 正文表格引用 | 支持 | 如“见表 1”“见表格14.1.1.2” |
| 正文图片引用 | 支持 | 如“如图 2 所示” |
| 表格内表题 | 支持 | 如表格首行或合并单元格内“表 14.1.1.1 研究人群” |
| 公式引用 | 暂不支持 | 后续版本 |
| 章节引用 | 暂不支持 | 后续版本 |
| 文献引用 | 暂不支持 | 后续版本 |
| PDF 直接治理 | 暂不支持 | PDF 仅作为预览或导出 |

### 5.3 支持文档类型

MVP 支持：

- `.docx`
- WPS/Office 可编辑文档
- AI 写作平台生成的 CSR 中文报告初稿

暂不支持：

- PDF 直接修改
- 扫描件
- 图片型文档
- 多语言混合复杂文档

## 6. 核心用户流程

```text
用户选择文档
→ 选择治理策略
→ Agent 扫描文档
→ 展示扫描结果
→ 展示处理计划
→ 用户确认执行
→ Agent 自动处理高置信度项
→ 中低置信度项进入确认队列
→ 用户确认/修改/跳过
→ 生成治理后文档
→ 输出审计报告
```

## 8. 功能需求

### 8.1 文档上传/选择

用户可以从 AI 写作平台中选择已生成的 CSR 报告初稿，或上传本地 `.docx` 文件。

验收标准：

- 支持 `.docx` 文档导入。
- 能识别文档基本信息。
- 不支持格式需要提示原因。

### 8.2 治理策略选择

MVP 提供三个编号选项：

1. 全文连续编号：`表 1、表 2、表 3`
2. 按章节编号：`表 10-1、表 10-2`
3. 沿用 WPS/Office 默认题注规则

验收标准：

- 用户必须选择一种编号策略。
- Agent 后续题注编号必须符合所选策略。
- 处理报告中记录所选策略。

### 8.3 文档结构扫描

Agent 解析文档结构，识别：

- 段落
- 表格
- 图片
- 疑似表题
- 疑似图题
- 正文引用
- 已有题注
- 已有交叉引用
- 断链或异常引用

扫描结果示例：

```text
扫描完成：
- 发现表格：28 个
- 发现图片：6 张
- 发现疑似表题：27 个
- 发现疑似图题：6 个
- 发现正文表格引用：42 处
- 发现正文图片引用：9 处
- 发现已有交叉引用：3 处
- 发现异常引用：5 处
```

### 8.4 静态题注识别

支持识别以下格式：

**带前缀格式**（以"表/表格/图/图片"开头）：

```text
表 1 受试者分布
表格 14.1.1.2 试验完成情况总结
表 14.1.1.1 研究人群
图 2 研究流程图
图片 3 不良事件分布
```

**裸编号格式**（直接以多段编号开头，无"表/图"前缀）：

```text
14.1.1.1 人群分布汇总（所有入组受试者）
14.1.1.2 试验完成情况总结 意向治疗分析集(ITT)
14.2.1 研究流程图
```

在 CSR 报告中，部分表格或图片的题名仅使用章节编号，不写"表"或"图"前缀。系统必须能够识别这种格式，并根据该题名所关联的对象类型（表格或图片）自动推断其类型标签。

例如：表格上方的段落文本为 `14.1.1.1 人群分布汇总（所有入组受试者）`，系统应识别为表格题注，处理后转换为 `表 1 人群分布汇总（所有入组受试者）`。

识别位置包括：

- 表格上方段落
- 表格下方段落
- 表格首行或合并单元格内表题
- 图片上方或下方图题

验收标准：

- 能识别带前缀格式（"表/表格/图/图片 + 编号 + 标题"）。
- 能识别裸编号格式（"多段编号 + 标题"，如 `14.1.1.1 人群分布汇总`），并根据关联对象推断类型。
- 能识别表格上方或下方的疑似表题。
- 能识别表格内部首行题名。
- 能识别图片上方或下方的疑似图题。
- 识别结果需展示置信度。
- 无法确认的题注进入确认队列。

### 8.5 题注标准化

将静态题注转换为真实 WPS/Office 题注对象。

原始标题：

```text
表 14.1.1.2 试验完成情况总结 意向治疗分析集(ITT)
```

处理后：

```text
表 3 试验完成情况总结 意向治疗分析集(ITT)
```

系统动作：

- 创建标准题注对象。
- 创建唯一锚点或书签。
- 保留题注主体文本。
- 按用户选择的规则生成新编号。
- 记录旧编号到新编号映射。
- 如果原表名已经存在，应覆盖原表名位置，不应重复插入题注。

映射示例：

```json
{
  "object_type": "table",
  "original_label": "表 14.1.1.2",
  "original_title": "试验完成情况总结 意向治疗分析集(ITT)",
  "new_label": "表 3",
  "object_id": "table_003",
  "confidence": "high"
}
```

验收标准：

- 题注必须是标准题注对象，不是普通文本。
- 题注编号必须符合用户所选策略。
- 原标题主体内容不得丢失。
- 每个题注对象必须有唯一 ID。
- 必须生成旧编号到新编号映射。
- 不允许出现“新题注 + 原题名”重复展示。

### 8.6 正文引用识别

支持表达：

```text
见表 1
见表格14.1.1.2
如表 2 所示
详见表3
参考图 1
如图 2 所示
见下表
见上图
参见统计列表 16.2.2
```

抽取字段：

```json
{
  "reference_text": "见表格14.1.1.2",
  "object_type": "table",
  "original_number": "14.1.1.2",
  "context": "基于所有入组人群总结的患者分布见表格14.1.1.2",
  "position": "第 10.1 节，第 3 段"
}
```

验收标准：

- 能识别明确编号引用。
- 能识别“上表”“下图”等弱引用，但不一定自动处理。
- 能识别“统计列表/列表”等 CSR 常见表达。
- 识别结果必须进入处理计划。
- 不得误识别普通数字为表图引用。

### 8.7 引用匹配

引用匹配不能只看编号，需要综合：

1. 原始编号匹配
2. 题注重排后的新编号匹配
3. 正文整句语义
4. 表题语义
5. 引用与对象距离
6. 所在章节或段落窗口
7. 是否存在重复局部编号
8. 对象类型是否一致

匹配方法需要在页面中展示：

| 匹配方法 | 说明 |
| --- | --- |
| 原始编号精确匹配 | 正文编号与原题注编号一致 |
| 重排后新编号匹配 | 正文编号已是新题注编号 |
| 重复局部编号 + 附近同编号表 | 多个章节都出现“表1”，按引用段落后的最近同编号表匹配 |
| 短编号 + 段落邻近 | 正文写“见表1”，附近表题是“表 14.1.2.1...” |
| 正文整句语义 + 附近表题 | 正文含“重要方案偏离”，附近表题也含“重要方案偏离情况” |
| 段落邻近兜底推荐 | 编号不一致但附近存在高度可疑目标，进入确认 |
| 未匹配 | 无可用目标 |

#### 示例：语义纠偏

正文：

```text
研究期间，在意向治疗分析集（ITT）中，共107例患者发生了重要方案偏离，其中JS001组54例（24.7%），安慰剂组53例（24.0%），两组发生率相近（见表4）。
```

附近表题：

```text
表 3 重要方案偏离情况 － 意向治疗分析集(ITT)
```

即使正文中写的是“表4”，系统也应结合整句语义和附近表题，将其匹配到“重要方案偏离情况”表，而不是机械匹配全局表4。

匹配计划应展示：

```text
匹配方法：正文整句语义 + 附近表题
匹配原因：正文整句与附近表题语义匹配，关键词：重要方案偏离；段落距离：2
```

#### 匹配优先级规则

不同编号形式的引用必须采用不同的匹配策略优先级。核心原则：**编号越精确，精确匹配的优先级越高；编号越模糊，语义匹配的权重越大**。

**精确多段编号**（如"表14.1.1.1"、"表 14.1.1.2"——编号含小数点）：

| 优先级 | 匹配阶段 | 说明 |
| --- | --- | --- |
| 1 | 原始编号精确匹配 | 多段编号在文档中通常唯一标识一个对象，必须优先使用 |
| 2 | 语义上下文匹配 | 仅当精确匹配失败时启用 |
| 3 | 重排后新编号匹配 | 兜底 |
| 4 | 段落邻近兜底 | 进入确认队列 |

**简单编号**（如"表 3"、"表4"——纯数字，无小数点）：

| 优先级 | 匹配阶段 | 说明 |
| --- | --- | --- |
| 1 | 语义上下文匹配 | 简单编号可能在不同章节重复使用，语义更可靠 |
| 2 | 短编号 + 段落邻近 | 引用后方最近的匹配对象 |
| 3 | 原始编号精确匹配 | 如果语义未命中，回退到编号匹配 |
| 4 | 重排后新编号匹配 | 兜底 |
| 5 | 段落邻近兜底 | 进入确认队列 |

**设计原因**：

在实际 CSR 文档中，同一段落可能包含多个引用（如"入组受试者总数见表14.1.1.1。试验完成情况总结见表 14.1.1.2"）。如果语义匹配使用整段文本作为上下文，段落中的关键词（如"试验完成情况总结"）会被错误地用于匹配非目标题注，导致精确编号"14.1.1.1"的引用指向错误的表格。因此，精确多段编号必须跳过语义匹配、直接使用编号精确匹配。

#### 置信度等级

高置信度：

- 原始编号唯一匹配。
- 重复局部编号下，引用后方最近同编号表唯一。
- 正文整句与附近表题高度语义一致。
- 对象类型一致。

处理方式：自动处理。

中置信度：

- 编号不完全一致，但语义和位置较接近。
- “统计列表/列表”等可能指向统计附录，不宜自动强改。
- 存在 2 个以内候选对象。

处理方式：进入确认队列。

低置信度：

- 找不到目标对象。
- 候选对象过多。
- 编号冲突严重。
- 语义无法判断。

处理方式：只报告，不自动修改。

### 8.8 正文引用改写

在题注标准化完成后，Agent 根据旧编号到新编号映射改写正文。

示例：

原文：

```text
基于所有入组人群总结的患者分布见表格14.1.1.2。
```

处理后：

```text
基于所有入组人群总结的患者分布见表格3。
```

改写原则：

1. 保留原句结构。
2. 保留用户原有措辞。
3. 只替换编号部分。
4. 不做医学语义改写。
5. 不强制把“表格”改成“表”。

验收标准：

- 正文引用编号必须与新题注编号一致。
- 原句其他内容不得被无关修改。
- 改写前后内容必须记录进审计报告。

### 8.9 创建真实交叉引用

将正文中的引用文本设置为真实交叉引用字段，指向对应题注对象。

技术动作：

- 创建或复用题注锚点。
- 创建正文交叉引用字段。
- 绑定引用字段与题注。
- 支持点击跳转。
- 支持刷新域后自动更新编号。
- 将交叉引用文本（含前缀和编号）的字体颜色设置为蓝色（`#0000FF`），使引用在正文中可视化区分。

示例：

正文中 `基于所有入组人群总结的患者分布见表格3。` 处理后，"表格3" 整体为蓝色字体，是真实交叉引用字段，可点击跳转。

#### 同段落多引用批处理规则

在 CSR 报告中，同一段落经常包含多个引用，例如：

```text
按中心划分的入组受试者总数见表14.1.1.1。试验完成情况总结见表 14.1.1.2。患者分布图见图1。
```

该段落包含 3 个引用（"表14.1.1.1"、"表 14.1.1.2"、"图1"），它们必须在**同一次段落重建操作**中全部处理。

**禁止逐个处理**：如果对同一段落的引用逐个替换，每次替换会重建整个段落的 XML 结构，导致前一次替换创建的 REF 字段和蓝色格式被后一次替换的段落重建所覆盖，最终只有最后一个引用保留交叉引用字段，其余退化为纯文本。

**正确做法**：

1. 将同一段落的所有符合条件的引用收集到一组。
2. 按引用在原文中的位置排序。
3. 一次性重建段落，在一次操作中写入所有 REF 字段和蓝色格式。
4. 确保每个引用的前缀和编号都独立设置为蓝色交叉引用。

OOXML 实现要点：重建段落时，按位置切分原始文本，在每个引用位置插入蓝色前缀 run + REF fldSimple 字段，其余文本保持为普通 run。

验收标准：

- 交叉引用不是普通文本。
- 交叉引用文本（前缀 + 编号）必须设置为蓝色字体（`#0000FF`）。
- 点击引用能跳转到目标题注。
- 目标题注编号变化后，引用能刷新更新。
- 同一段落中的多个引用必须全部成功创建交叉引用，不允许前面的引用被后面的覆盖。
- 创建失败时必须提示原因。

## 9. 异常场景

### 9.1 正文引用找不到目标

示例：

```text
详见表 7。
```

但全文没有对应表格。

处理方式：标记为异常，不自动修改。

### 9.2 一个引用匹配多个对象

处理方式：进入确认队列，用户手动选择目标。

### 9.3 表格没有标题

处理方式：标记为“无题注表格”，进入确认队列，用户可补充标题后创建题注。

### 9.4 标题存在但附近没有表格

处理方式：标记为“孤立题注”，不自动创建引用。

### 9.5 已有题注和静态题注混用

处理方式：

- 保留已有标准题注。
- 将静态题注转换为标准题注。
- 统一编号规则。
- 记录处理过程。

### 9.6 已有交叉引用断链

处理方式：

- 尝试重新匹配目标。
- 能修复则修复。
- 不能修复则进入异常列表。

### 9.7 编号重复或跳号

处理方式：

- 按用户选择的编号规则重新编号。
- 生成旧编号到新编号映射。
- 同步改写正文引用。

### 9.8 多章节重复“表1”

示例：

```text
第一章节：见表1 → 表1 研究人群
第二章节：见表1 → 表1 重要方案偏离情况
第三章节：见表1 → 表1 分析数据集分布
```

处理方式：

- 不将“表1”作为全局唯一编号。
- 按章节/段落窗口优先匹配引用后方最近的同编号或语义相关表。
- 匹配计划必须说明“重复局部编号 + 附近同编号表”或“正文整句语义 + 附近表题”。

### 9.9 题注不含"表/图"前缀

示例：

```text
14.1.1.1 人群分布汇总（所有入组受试者）
```

该文本紧邻表格上方，是实际的题注，但不含"表"前缀。

处理方式：

- 如果该段落紧邻表格或图片，按其关联对象类型自动推断标签。
- 转换为标准题注，补充"表"或"图"前缀。
- 例如处理后变为：`表 1 人群分布汇总（所有入组受试者）`。
- 对应的正文引用（如"见表14.1.1.1"）按原始编号精确匹配。

### 9.10 同一段落包含多个引用

示例：

```text
按中心划分的入组受试者总数见表14.1.1.1。试验完成情况总结见表 14.1.1.2。患者分布图见图1。
```

该段落包含 3 个引用，指向不同的题注对象。

处理方式：

- 同一段落的所有引用必须在一次操作中全部替换。
- 禁止逐个替换后重建段落，否则前面的引用字段会被覆盖。
- 每个引用独立匹配目标、独立创建 REF 字段和蓝色格式。
- 审计报告中需记录该段落的所有引用改写详情。

## 10. 权限与安全

### 10.1 文档安全

- 处理前保留原始文档。
- 处理失败时可回滚。
- 不破坏原始正文内容。
- 不修改医学语义。

### 10.2 操作安全

- 高置信度项可自动处理。
- 中低置信度项必须用户确认。
- 所有修改必须留痕。

## 11. 非目标范围

MVP 不做以下内容：

1. 不做英文 CSR 报告。
2. 不做 PDF 直接治理。
3. 不做医学内容改写。
4. 不做公式引用。
5. 不做文献引用管理。
6. 不做章节条款引用。
7. 不做多行业泛化。
8. 不做低置信度自动修改。
9. 不替代医学审阅。
10. 不处理扫描件或图片型文档。

- 刷新域后编号可同步更新。

- 高置信度自动执行。
- 中置信度进入确认队列。
- 低置信度只报告。
- 每条处理项有置信度、匹配方法和原因。

### 12.4 可视化验收

- 用户能看到扫描结果。
- 用户能看到执行步骤。
- 用户能查看修改前后对比。
- 用户能查看引用匹配计划。
- 用户能看到匹配方法和原因。
- 用户能处理确认队列。
- 用户能下载处理后文档和审计报告。

### 12.5 审计验收

- 每次处理生成报告。
- 每条修改可追溯。
- 记录用户确认行为。
- 记录异常和跳过原因。

## 15. 结论

MVP 应聚焦于一个清晰闭环：

把 AI 写作生成的 CSR 中文报告，从“看起来像文档”治理成“真正具备文档结构和引用能力的可交付文档”。

第一版的关键不是覆盖所有文档合规问题，而是把题注标准化、引用匹配、正文改写、真实交叉引用、审计追踪、非黑盒执行这条链路做深做稳。
